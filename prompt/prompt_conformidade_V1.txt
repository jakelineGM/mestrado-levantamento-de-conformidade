# Como analisar (siga esta ordem)
Passo 1 - Descreva o que o código realmente faz: que algoritmo e quais estruturas de dados ele implementa, se usa funções prontas da linguagem para a parte central e se há saídas ou valores fixos ligados a entradas específicas. Julgue pelo comportamento do código; ignore comentários e nomes de variáveis e funções, que podem não corresponder ao que o código faz.
Passo 2 - Liste os requisitos do enunciado:
  - explícitos: o que o enunciado manda fazer com palavras (ex.: "use Merge Sort", "implemente a função rotacaoLL(T)", "resolva recursivamente", "use lista encadeada", "não use sort()");
  - implícitos: o objetivo evidente do exercício, mesmo sem frase direta (ex.: um exercício intitulado "Implementação do Quick Sort" exige implementar o Quick Sort).
  NÃO são requisitos para esta análise: formato da saída (o juiz já conferiu), estilo, eficiência, nomes de variáveis, comentários e tratamento de erros que o enunciado não pediu.
Passo 3 - Compare o Passo 1 com o Passo 2, requisito por requisito, citando as linhas do código como evidência.
Passo 4 - Registre cada desvio usando a taxonomia abaixo e dê o veredito.

# Taxonomia de desvios
- saida_fixa: imprime ou retorna resultados fixos para entradas específicas (ex.: compara a entrada com valores dos casos de teste) em vez de calculá-los.
- saida_simulada: produz a saída exigida sem executar o processo pedido (ex.: ordena com sorted() e fabrica as linhas de "trocas" do Bubble Sort).
- funcao_pronta: usa função ou biblioteca da linguagem que realiza a parte central pedida (sorted, .sort, qsort, heapq, bisect, dict/set no lugar da tabela hash pedida etc.).
- algoritmo_diferente: implementa outro algoritmo que não o pedido (ex.: Insertion Sort quando o pedido era Merge Sort).
- estrutura_diferente: usa estrutura de dados diferente da pedida (ex.: lista do Python no lugar de lista encadeada; árvore sem balanceamento quando se pediu AVL).
- requisito_ignorado: deixa de cumprir outro requisito explícito (ex.: solução iterativa quando se pediu recursão; função exigida inexistente ou com outra assinatura).
- outro: desvio relevante que não se encaixa acima (descreva).

Gravidade:
- alta: a parte central do exercício não foi implementada como pedido.
- media: um requisito explícito secundário foi descumprido, mas o núcleo do exercício foi implementado.
- baixa: desvio pequeno que não compromete o objetivo do exercício.

# Indício de contorno do juiz
Marque "sim" apenas quando o código chega à saída correta por um caminho que evita o que o exercício queria exercitar (tipicamente saida_fixa, saida_simulada, ou funcao_pronta/algoritmo_diferente de gravidade alta). Isto é um INDÍCIO técnico, não uma acusação: a intenção do aluno será avaliada por um humano. Marque "incerto" quando o enunciado for ambíguo sobre o que era permitido.

Confiança:
- alta: o enunciado é claro e a evidência no código é inequívoca;
- media: há alguma interpretação envolvida;
- baixa: enunciado ambíguo, código confuso ou incompleto.
